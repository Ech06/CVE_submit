# 漏洞：GNU Binutils ld 在添加畸形符号/版本信息时 `elf_link_add_object_symbols` 存在空指针解引用（NULL Dereference）

**项目：** GNU Binutils / GNU ld (https://sourceware.org/git/?p=binutils-gdb.git)
**版本：** 漏洞存在于 binutils 2.47（发布包版本日期 `20260726`）及开发快照 `2.47.50.20260722`（提交 `640a79623`），截至本文撰写（2026-08-16）尚无上游修复
**日期：** 2026-07-28
**严重性：** 中危（MEDIUM）
**OWASP：** 不适用 - 原生二进制解析内存安全
**CWE：** CWE-476 - 空指针解引用

------

## 受影响文件

```text
bfd/elflink.c（`elf_link_add_object_symbols`）
ld/ldlang.c（`load_symbols`、`open_input_bfds` 调用路径）
```

## 根本原因

畸形的符号表和/或版本信息表在 `elf_link_add_object_symbols()` 添加版本化符号的过程中，使未校验的符号/别名/节指针在为 NULL 时即被解引用：

- `bug_5.o` 崩溃于 `bfd/elflink.c:6080`（SEGV 读取 `0x78`）；
- `bug_6.o` 与 `bug_16.o` 先在 `bfd/elflink.c:5522` 触发 BFD 断言失败，随后在 `:5527` 崩溃（SEGV 读取 `0x4a`）。在 2.47 发布包中两者落在同一行（发现表中开发快照的 `:5528` 与之对应，为同一处代码）。

三个 PoC 指向同一类根因：版本化符号添加期间对 symbol/alias/section 指针缺少校验。报告者判断该问题可能是对 bug 33476 的不完整修复。截至本文撰写，上游尚未提供修复提交。

## 复现步骤

以下命令假定本报告的 `pocs` 目录与构建的 `binutils-gdb` 目录相邻：

```bash
git clone https://sourceware.org/git/binutils-gdb.git binutils-gdb
cd binutils-gdb
git checkout 640a79623
CC=gcc CFLAGS='-g -O1 -fsanitize=address -fno-omit-frame-pointer -fno-common' \
LDFLAGS='-fsanitize=address' \
./configure --disable-gdb --disable-gdbserver --disable-sim --disable-cet \
            --disable-werror --disable-nls --enable-targets=x86_64-linux-gnu MAKEINFO=true
make -j
```

binutils 2.47 发布包（版本日期 `20260726`）同样复现（三个 PoC 全部复现）。运行 PoC：

```bash
export ASAN_OPTIONS="abort_on_error=0:symbolize=1:detect_leaks=0:allocator_may_return_null=1:halt_on_error=1"
./ld/ld-new --shared --gc-sections -o /dev/null ../pocs/34447/bug_5.o    # :6080
./ld/ld-new --shared -o /dev/null ../pocs/34447/bug_6.o                  # :5527
./ld/ld-new --shared -o /dev/null ../pocs/34447/bug_16.o                 # :5527
```

## 影响

精心构造的目标文件可在链接器读取输入符号阶段使 `ld` 崩溃，造成拒绝服务。该阶段发生在任何实际链接工作之前，因此对不可信目标文件执行链接的构建服务、编译农场或 CI 流水线均可能被单一畸形输入终止。

## 建议修复

在 `elf_link_add_object_symbols()` 的版本化符号处理路径中，对符号、别名及节指针进行充分校验：当输入的符号/版本表不一致时应报告链接错误并中止，而非解引用空指针；并将这三个畸形样本纳入 AddressSanitizer 回归覆盖。截至本文撰写上游尚无修复，建议在修复发布前避免对不可信目标文件直接运行 `ld --shared`，或在上游修复后及时升级。
